## 当前结论

- 手部阶段 `interhand_bedlam_c` 已完成，InterHand-test 全量对等结果为 **OSX normal 19.58mm → `_c` snapshot_8 16.82mm**，手部增益 **-2.76mm / -14%**。
- 面部阶段 `face_ubody_e` 已完成，EHF Face 回到约 **6.20mm**，但原始 OSX 约 **6.09mm**，所以脸不是有效贡献点。
- UBody 自然手 2D 评测已接入，当前 `test_sample_interval=10`，`fps=3` 抽帧后样本量足够做快速比较。
- 最新 UBody 结果显示：微调后模型在自然手 2D 上低于原始 OSX；Stage 2 冻手训脸没有继续改变手，问题应来自更早的手部微调/decoder 路径。
- UBody `[wa]` per-finger / per-level 诊断已完成（三档：OSX / `face_ubody_e` / `pretrained` 随机-ish 手头参照）。退化模式收敛：**沿指节深度递增、指根不动、tip 最差，整体接近随机-ish 手头的末端优先退化曲线**，我们处在 OSX→`pretrained` 退化区间 72%；该诊断已用于设计 Stage 3。
- **Stage 3 `joint_polish_f` 已收口，终点定 `snapshot_2`**：InterHand PA **16.76mm**（-14% vs OSX 19.58，目前最好）/ wrist-rel 84.32mm；UBody 整手 `[wa]` NME 0.250→**0.229**（接近 OSX 0.219 但未追平，epoch 2 死平在 0.228-0.229=平台）；EHF Face 6.25mm（微退、噪声级）。Phase 2（epoch 2，lr~5e-7）本质 wash：InterHand 微降、EHF 微退、UBody 不动。已停训不跑 epoch 3。snap1 为"无退化"保守替代，与 snap2 实质等价。

UBody natural-hand 2D，`output/eval_ubody` / `output/eval_joint_polish_f`：

| 指标 | 原始 OSX | `face_ubody_e` | `joint_polish_f` snap1 | `joint_polish_f` snap2(终点) |
|---|---:|---:|---:|---:|
| Evaluated hands | 3446 | 3446 | 3446 | 3446 |
| `[abs]` PCK@0.2 | 0.422 | 0.383 | 0.406 | 0.406 |

伪 GT PA-MPJPE 仍不能反映自然手质量；判断自然手以真实 2D hand keypoint 的 `[abs]` / `[wa]` 为主。Stage 3 验证了 UBody 自然手监督 + predicted ROI + mixed data 这个组合配方有效，但还没有单独隔离“GT 框注入/crop 分布差”这一单因子。

这里的“原始 OSX”来自 `output/eval_ubody/result/UBody_result.txt`：top-level eval 使用
`--decoder_setting normal` 且没有 `--continue_train_path`；snapshot 子目录使用 `pytorch` 两步加载
`face_ubody_e` checkpoint。当前 per-finger 结果目录里有 snapshot_0/4；snapshot_8 由冻结手权重等价推断。`result/pretrained/` 是 pytorch 映射预训练分支，保留未覆盖随机-ish 手头，用作退化参照而非严格下界。

per-level `[wa]` NME（退化沿指节深度递增，Stage 3 主要回收 j3/tip）：

| level | OSX | `face_ubody_e` | `joint_polish_f` snap1 | `pretrained` | snap1-OSX |
|---|---:|---:|---:|---:|---:|
| j1 指根 | 0.205 | 0.208 | 0.206 | 0.207 | +0.001 |
| j2 | 0.221 | 0.236 | 0.225 | 0.241 | +0.004 |
| j3 | 0.231 | 0.270 | 0.242 | 0.286 | +0.011 |
| tip 指尖 | 0.263 | 0.337 | 0.287 | 0.367 | +0.024 |

tip/j1 放大比：OSX 1.28 → `face_ubody_e` 1.62 → `joint_polish_f` snapshot_1 1.39 → `pretrained` 1.77。结论：退化主要是整体末端能力下降，Stage 3 已把末端斜率显著拉回，但仍略差于原始 OSX。

注意：已核对 `smpl_x.orig_hand_regressor` 与 UBody GT 手关键点顺序，二者都是
`wrist, thumb, index, middle, ring, pinky`。不要用 `human_models.py` 里的旧
`orig_joints_name` 解码 `J_regressor` 行号，它对 SMPL-X 22+ 行有误导。

## 已实现：UBody `[wa]` Per-Finger 诊断

`data/UBody/UBody.py` 的 `evaluate()` / `print_eval_result()` 已新增 `[wa-finger]`（thumb/index/middle/ring/pinky）和 `[wa-level]`（j1/j2/j3/tip）NME + 有效计数 N。wrist 只对齐一次，归一化用整手 GT bbox diagonal，`vf.sum()>=2` 才统计；并加了 UBody hand order 显式校验。

**判读口径（下次看 per-finger 结果必读）**：per-finger/per-level 是各自可见子集上的均值，每组进入统计的手不同，**不要用五指 NME 简单平均去对账整手 `[wa]` NME**；横向比手指也要同时看 `N`（tip/j1 的 N 会因指尖常遮挡而明显小于指根，属预期）。最适合看同一根手指/同一 level 的 OSX vs 我们 delta。

## 常用训练命令

Stage 3 联合 polish（修末端自然手泛化；先短跑 2-4 epoch，别直接 12）。与 `main/train.sh` 活动命令一致：

```bash
cd /workspace/myosx/main
export UBODY_ANNOTATION_DIR=/workspace/myosx/dataset/UBody/annotations_filtered
python train.py --gpu_ids 0 --lr 5e-5 --lr_mult 0.1 \
  --train_batch_size 64 --num_thread 8 --end_epoch 4 --phase1_epochs 2 \
  --exp_name output/joint_polish_f --decoder_setting pytorch --encoder_setting osx_l --grad_clip 1.0 \
  --pretrained_model_path ../pretrained_models/osx_l.pth.tar \
  --init_trained_path ../output/face_ubody_e/model_dump/snapshot_4.pth.tar \
  --train_face_modules --posnet_lr_mult 0.5 \
  --bedlam_use_hand_roi_quality --bedlam_no_hand_img_loss \
  --ubody_use_hand_roi_quality --save_iters 1280
```

`--save_iters 1280`（新增，可选）：每 ~1/3 epoch 在中途存 `snapshot_{epoch}_itr1280/2560.pth.tar` 作为评估候选点，与 epoch 末快照分开命名、互不覆盖（每个 ~399M）。中途快照定位为评估点，续训仍以 epoch 为粒度。`0`/不传＝关闭。

前置（必须改 `config.py`，CLI 不覆盖数据集选择）：`trainset_3d=['BEDLAM','InterHand26M','UBody']` 且 `trainset_3d_sample_prob={'BEDLAM':0.20,'InterHand26M':0.35,'UBody':0.45}`（不补 UBody 概率会报 Missing sample probabilities）。UBody ROI gate 阈值走 `config.py` 默认 0.6/8（诊断起点）；正式跑前先 `--end_epoch 1` 短跑看 `[ubody] hand_roi_gate_coverage/pass/n_valid` 校准，再按需改 config.py。Stage 3 前确认 UBody 用 box_net 预测框、不注入 GT 框。
