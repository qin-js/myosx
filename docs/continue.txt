## 当前结论（2026-06-27 重大更新）

- **编码器移植 bug 已修复**：`StandardViT`(pytorch 路径)的 `PatchEmbed` 卷积 padding 之前是 0，OSX MMCV ViT 是 2，导致 patch 特征系统性错（`img_feat` 相对 OSX 偏 24%，但形状相同所以一直隐形）。修复后(`common/nets/vit.py`，padding=2 + LayerNorm eps 1e-6)，pytorch 编码器与 OSX **逐比特一致**。验证工具 `tool/analysis/encoder_compare.py`、`crosspath_compare.py`。
- **手头对修复完全鲁棒、无需重训**：`snapshot_2`(旧编码器训出)直接在修复编码器上评测，InterHand PA 16.76→**16.78**、UBody/HInt `[wa]` 纹丝不动。snap2@修复是可用工作基线。
- **编码器修复净赚**：UBody `[abs]` 0.324→**0.316**、EHF Face 6.25→**6.15**，免费向 OSX 收敛（之前的"自然手/[abs]退化"有一块就是这个 bug）。
- **唯一真问题被干净隔离**：UBody `[wa]` 0.229 vs OSX 0.219 的 **0.010**，在 body 与 OSX 逐比特一致后仍在 → 100% 是手头自然图相对手指 articulation。配对 bootstrap CI `[-0.0117,-0.0087]`、显著。
- **InterHand −14% 的 caveat**：OSX 原始训练集**不含 InterHand26M**，−14% 本质是"我们微调 vs OSX 零样本"，论文需补公平基线或改用 held-out(HInt) 当 headline。

## 下一步建议

1. **干净地打 UBody `[wa]` 那 0.010**（现在无 confound）：候选 — Route C(`--train_hand_roi`，解冻 `hand_roi_net` 小 LR 共适应，已实现、默认关闭；warm-start snap2，kill 线 `[wa]`≤0.224)；末端 2D loss 加权(差距集中 tip/j3)；更多自然手监督。
2. **处理 InterHand 公平基线**：补一个"在 InterHand 上同数据微调的 OSX"，或把 headline 让位给 held-out HInt。
3. 身体 shape T1(`--train_body_shape`)仍是独立附带线，默认关闭。

## 常用评估命令（pytorch 路径现在自动带编码器修复）

```bash
cd main
# UBody natural-hand（加 --dump_analysis 可同时出 bootstrap/crosspath npz）
export UBODY_ANNOTATION_DIR=/workspace/myosx/dataset/UBody/annotations_filtered
python test.py --gpu 0 --testset UBody --exp_name output/eval_x \
  --decoder_setting pytorch --encoder_setting osx_l \
  --pretrained_model_path ../pretrained_models/osx_l.pth.tar \
  --continue_train_path ../output/joint_polish_f/model_dump/snapshot_2.pth.tar

# InterHand 全量： --testset InterHand26M --interhand_eval_split test --max_eval_iters -1
# HInt：          --testset HInt --hint_root /workspace/HInt_annotation_partial --hint_split test --hint_sources epick,newdays
# 编码器忠实度探针： 两次 test.py 各加 --dump_encoder_n 32 (normal / pytorch)，再跑 tool/analysis/encoder_compare.py
```
