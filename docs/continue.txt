## 当前结论（2026-06-27 重大更新）

- **编码器移植 bug 已修复**：`StandardViT`(pytorch 路径)的 `PatchEmbed` 卷积 padding 之前是 0，OSX MMCV ViT 是 2，导致 patch 特征系统性错（`img_feat` 相对 OSX 偏 24%，但形状相同所以一直隐形）。修复后(`common/nets/vit.py`，padding=2 + LayerNorm eps 1e-6)，pytorch 编码器与 OSX **逐比特一致**。验证工具 `tool/analysis/encoder_compare.py`、`crosspath_compare.py`。
- **手头对修复完全鲁棒、无需重训**：`snapshot_2`(旧编码器训出)直接在修复编码器上评测，InterHand PA 16.76→**16.78**、UBody/HInt `[wa]` 纹丝不动。snap2@修复是可用工作基线。
- **编码器修复净赚**：UBody `[abs]` 0.324→**0.316**、EHF Face 6.25→**6.15**，免费向 OSX 收敛（之前的"自然手/[abs]退化"有一块就是这个 bug）。
- **唯一真问题被干净隔离**：UBody `[wa]` 0.229 vs OSX 0.219 的 **0.010**，在 body 与 OSX 逐比特一致后仍在 → 100% 是手头自然图相对手指 articulation。配对 bootstrap CI `[-0.0117,-0.0087]`、显著。
- **InterHand −14% 的 caveat**：OSX 原始训练集**不含 InterHand26M**，−14% 本质是"我们微调 vs OSX 零样本"，论文需补公平基线或改用 held-out(HInt) 当 headline。

## 下一步建议

**decoder 坐标精修结构线已判定「不打闸」（7-03 L728 负结果收口）。InterHand PA 的杠杆不在 2D 坐标机制——PA 是 Procrustes 对齐、只测手内 3D articulation，由 `hand_regressor` 的 3D pose 输出决定，与我们一直在优化的 2D 坐标精修/aux 2D loss 近正交。7-04 补：两个对靶 pose 杠杆也已试完，InterHand PA 线整体封口。7-04 晚再补：HInt "赢"被 fairbase 三测修正为**精确平局**（0.480 vs 0.480），2D 正交性结论反而更硬（hand-crop 2D 对 decoder 家族饱和、由冻结管线+数据决定）；同时 OSX decoder 死代码发现坐实"7-01 大改瞄错靶"。主线 = B（论文故事，headline 已换轴）。**

> **（2026-07-04 晚 状态）目标定位不变（相对 stock OSX 全绿、非顶会可发），方法 claim 落点换轴 = 「① whole-body 3D 手对公平基线全面赢（EHF 15.61 vs 16.85、UBody 10.00 vs 10.59）+ ② held-out 2D 不落后（HInt 精确平）+ ③ 高效冻结骨干 recipe + ④ 消融升级为"抗侵蚀归因"（rotmat 正/aux 正/L728 负 + 待补组件消融）」。InterHand 诚实略逊（16.53 vs 16.29，wrist-rel 85.09 vs 82.87），不 claim in-domain 优越。**

**A. InterHand PA 两个对靶杠杆已试完、封口（7-04）:**
1. **rotmat pose loss**（`--use_hand_rotmat_pose_loss`）= **正结果但触顶**：16.80→**16.53**(snap0，−0.27，与 L728 +0.25 反向 → 坐实 pose 空间才是对靶杠杆)，但 epoch1 平台、**未过闸 16.29(+0.24)**。当前栈天花板 ≈16.5（7-04 死代码发现后，"结构性"归因限定为 DCNv4 冷启 posnet+3 层 topo/occ+detach 这套栈，非"decoder 概念"）。**recipe 保留 rotmat + aux**。
2. **aux-off**（`--hand_aux_coord_loss_weight 0`）= **更差**（16.75→16.88 在退）→ aux 该留。⚠️ confound 注记：关 loss 后 bbox_embed 仍在无监督迭代参考点——此实验只证"装了坐标机制必须配监督"，不证"坐标机制优于 OSX 式固定参考点"（OSX 的坐标机制是死代码，见 7-04 追加①）。
   → 结论：PA 从 16.78 推到 **16.53**（护栏全守），穿不过 16.29。**不再纠缠**，认 in-domain 略负。可选收尾：补对照 gate snap1 +1ep rotmat 关，把 16.53 干净归给 rotmat（非必须）。

**B.（现主线）headline = whole-body 手部抗侵蚀 + 高效 recipe + 消融:**
3. **headline = whole-body 3D 手（对公平基线的赢）**：OSX-ft 拿 in-domain 的代价 = EHF Hands 15.97→**16.72~17.13**、UBody Hands 10.29→~**10.4**——hand-heavy 微调经典侵蚀（7-05 fairbase 4ep 坐实：从 ep1 起不回落）；我们 16.53 的同时 EHF **15.61**、UBody **10.00**，两口径均优 stock+任意 epoch ft。写成「不为 in-domain 手 crop 基准过度特化 ↔ whole-body 全面赢，单模型无外部专家」，对位 H4W++。**HInt 降级为支撑证据**（0.480 精确平）。**诚实项**：in-domain 落后公平基线（InterHand ~1.2mm 且扩大、wrist-rel ~3.4mm）→ 主轴移到 whole-body（EHF/UBody/AGORA），InterHand 定位「手 crop 专项、诚实报告非主场」。~~待办 fairbase 4ep~~ **已完成（7-05）**。
4. **消融叙事升级**：Table 4 三行（rotmat 正/aux 正/L728 负）保留，新增核心问题「**哪个组件买来抗侵蚀**」（假设：aux 2D+热图监督是锚，OSX decoder 无锚故漂）。首推探针 = **posnet 换回 conv `PositionNet`（osx_l 可直接暖启）+ detach off**，一石二鸟：单变量测 7-04 追加①的最大嫌疑簇（DCNv4 冷启/脆弱/detach）+ 归因抗侵蚀来源；topo/occlusion 消融照旧必跑（方法节存在性论证）。**这是主模型定死后唯一剩余实验线，可开跑。**
5. **正交附带线（T1 已判负 7-06）**：UBody `[wa]` **不可用 T1 补绿**——拆分证明 `[wa]` 杠杆 100% 是 cam_z 投影几何（非 shape），而 cam_z 让 `[wa]↑` 与 `[abs]↓` 刚性耦合、冻结框架无法解耦（cam-only `[wa]` 0.205 反超但 `[abs]` 0.362 崩；shape-only 纯负债）。→ **whole-body 3D 口径本已全绿、不依赖 T1**，`[wa]`/`[abs]` 降为 2D 诊断、诚实标注 gap=body cam 几何；cam/shape 两 run 进 Table 4 归因行。teacher distillation 备选。
